it uses the working EBOOT, PRXs, and all other PE files, changes only
`win/wine/lib/wine/x86_64-windows/wow64.dll`, and crashes with the same
`virtual_setup_exception stack overflow 384 bytes` as the full split runtime.
The rebuilt DLL imports `kernel32.dll` and `ntdll.dll`; the working DLL imports
only `ntdll.dll` (verified with `x86_64-w64-mingw32-objdump -p`). Patch
`wine/orbis/base-patches/0613-wow64-import-kernel32-debug-helper.patch` adds
that import to fix a PE link dependency introduced by `debugstr_w()` calls in
`dlls/wow64/syscall.c`. Treat the added import as the **leading cause**, not
yet proven: replace or relocate those debug string calls so WoW64 can link
without an early `kernel32.dll` dependency, rebuild just `wow64.dll`, inspect
its import table, then package a one-DLL A/B. If the corrected DLL runs, test
the entire rebuilt PE set with that DLL replaced. The rebuilt PE `ntdll.dll`
pair (`ORBW00013`) and `wowprospero.dll` (`ORBW00014`) both worked alone.
`ORBW00015` (those three combined), `ORBW00016` (all x86_64 PE), and
`ORBW00017` (all i386 PE) remain uploaded but untested; they are lower priority
than fixing the isolated failure.

Do **not** use `ORBW00007` or `ORBW00008` as test results. Both failed in the
PS4 loader with `PRX_SCE_MODULE_LOAD_ERROR` before Wine started. Their ad hoc
packages omitted `sce_module/libc.prx` and `libSceFios2.prx`; `ORBW00009/10`
